# ADR-0005：Word 模板引擎

| 项目 | 内容 |
|---|---|
| 状态 | 接受 |
| 日期 | 2026-10-05 |
| 决策人 | 项目负责人 |
| 关联 | [10 Word 生成与模板规范](../10-doc-generation.md) |

## 1. 背景与问题

- 交付物是《卫星整星详细设计方案》Word，章节固定、表格多、需要出处标注与编号
- 要求：模板可由非程序员（工程师）维护；数据与排版分离；渲染前可校验占位符完整性

## 2. 备选方案

| 方案 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| A（选定） | docxtpl（Word 模板 + Jinja2 语法） | 模板用 Word 维护；数据 / 排版分离；占位符可扫描校验 | 动态表格语法需约定 |
| B | python-docx 纯代码构建 | 完全可控 | 排版硬编码，工程师无法改模板 |
| C | pandoc + reference.docx | Markdown 转 Word | 样式控制弱，复杂表格受限 |
| D | LaTeX → docx | 排版强 | 工具链重，偏离 Word 交付要求 |

## 3. 决策与理由

- 选择：**docxtpl**（基于 python-docx + Jinja2）
- 理由：
  1. 工程师可直接在 Word 里调整版式，程序只关心占位符
  2. 渲染前可扫描 `{{ }}` 占位符集合做完整性校验（渲染失败前置化）
  3. 轻量依赖，离线可用
- 约定：占位符命名与数据源映射见 [10](../10-doc-generation.md) 第 2 节；模板文件版本化（`templates/`）

## 4. 影响

- 复杂动态表格需遵守 docxtpl 的循环语法约定（写入 10 文档）
- 模板变更必须跑 [11 测试计划](../11-test-plan.md) 的文档回归用例
- 若未来输出格式扩展（PDF 等），本决策不影响 IR 层，只替换渲染层
