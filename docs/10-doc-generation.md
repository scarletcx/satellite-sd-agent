> 交付物本体是《卫星整星详细设计方案》Word。规则：**数字只来自 IR，LLM 只写叙述；每个数字带出处**。
> 引擎：docxtpl（ADR-0005）；模板：`templates/design-report-v1.docx`；本文档是模板的字段级规格。

## 1. 模板语法约定

| 语法 | 用途 | 示例 |
|---|---|---|
| `{{ path }}` | 数值 / 文本占位符 | `{{ power.sa.area }}` |
| `{{ path \| fixed(2) }}` | 小数位过滤 | `{{ mass.total \| fixed(1) }}` |
| 单位自动附加 | 渲染时按 IR `unit` 追加 | `{{ power.sa.area }} m²`（或在模板写单位，二选一，**统一为模板内写单位**） |
| `{%tr for item in budget.mass.items %}` … `{%tr endfor %}` | 表格行循环（docxtpl 表格语法） | 预算表行 |
| `{% if condition %}` … `{% endif %}` | 条件段落 | 无候选时省略选型表 |
| `{{ cite:S1 }}` | 引用上标 | 正文标注，附录展开 |

**占位符规则**：

1. 路径必须是 IR 中存在的已注册字段（渲染前扫描校验，缺失 → 失败）
2. 数值占位符仅接受 `verified`（或人工放行的 `warn`）参数，否则 A10 返回 409
3. 叙述文本中的数字也必须以占位符形式出现（S8 规则，[05](./05-agent-orchestration.md) §S8）

## 2. 章节规格（v1）

| 章节 | 模板标题 | 数据来源 | 表格 / 内容规格 | 叙述 |
|---|---|---|---|---|
| 1 概述 | `1 概述` | `mission_request.*` | 任务书摘要表（目标 / 轨道 / 寿命 / 载荷 / 约束） | LLM |
| 2 总体构型 | `2 卫星总体构型` | `system_design.configuration.*` | 构型类型、包络尺寸表 | LLM |
| 3 分系统配置 | `3 分系统配置` | `system_design.subsystems[]` | 表：分系统 / 组成 / 说明 / 依据 `[S#]` | LLM |
| 4 质量预算 | `4 质量预算` | `budget.mass.*` | 行表：项目 / 质量(kg) / 余量 / 来源；汇总行 + 余量口径 | — |
| 5 功耗预算 | `5 功耗预算` | `budget.power.*` | 表：负载 / 光照(W) / 阴影(W) / 占空比 / 来源；能量平衡小结 | — |
| 6 数据量预算 | `6 数据量预算` | `budget.data.*` | 表：速率 / 压缩比 / 单圈 / 每日 / 存储需求 / 下行能力 | — |
| 7 测控数传方案 | `7 测控数传方案` | `budget.link.*` + `orbit.windows` | 链路表：频段 / EIRP / G-T / Eb/N0 / 余量；过境窗口表 | LLM + 表 |
| 8 姿态确定与控制 | `8 姿态确定与控制方案` | `adcs.*` | 能力核对表：扰动力矩 / 需求动量 / 裕度 | LLM |

| 10 选型建议 | `10 关键器件与选型建议` | `component_candidates[]` | 表：类别 / 候选 / 关键指标 / 依据 `[S#]` | LLM + 表 |

**简化模型声明（ADR-0004）**：第 7、8、9 章必须包含固定段落「模型假设与适用范围」，内容含轨道/链路/ADCS 简化条件与误差范围（±值来自 [06](./06-calculation-verification.md) §3）。

## 3. 引用与假设标注

- 正文引用：上标 `[S1]`；同一来源复用编号；附录按出现顺序编号
- 合成语料：`[S3][合成]` 并在附录类型列注明
- 假设：正文脚注 `①`，附录台账对应；未确认假设不得出现在正文（V7 保证）

## 4. 生成流程（S9）

```
IR（verified 快照）+ narrative（占位符化）+ 模板 v1
  → ① 扫描模板占位符集合，与 IR 路径比对（缺失即失败，不产出半成品）
  → ② 渲染前门禁：存在 block → A10 409
  → ③ docxtpl 渲染 → document-v<N>.docx
  → ④ doc.check 自检 → check-report.json
  → ⑤ 版本号 +1 并登记 artifacts
```

**doc.check 检查清单**：

| # | 检查 | 规则 |
|---|---|---|
| 1 | 占位符残留 | 必须为 0 |
| 2 | 数字反查 | 文档中全部数值可在 IR 中定位（按值遍历） |
| 3 | 引用完整 | 每个 `[S#]` 在附录有记录；无悬空引用 |
| 4 | 单位齐全 | 表格数值列全部带单位 |
| 5 | 假设闭环 | 正文脚注与附录台账一一对应 |

| 用例 | 断言 |

## 6. 关键取舍

| 决策 | 备选 | 理由 | ADR |
|---|---|---|---|
| docxtpl | python-docx / pandoc | 模板可由工程师维护、渲染前可校验 | [0005](./adr/0005-doc-engine.md) |
| 单位写在模板内 | 程序自动追加 | 工程师可直接调整排版；程序只替换数值 | — |
| 叙述先生成、后渲染 | 渲染时边生成 | 快照一致、可复现 | — |
